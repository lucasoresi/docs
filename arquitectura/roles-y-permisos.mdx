## Descripción General

Optacost implementa un sistema de **Role-Based Access Control (RBAC)** que define qué puede hacer cada usuario según su rol asignado.

## Implementación Técnica

### Row Level Security (RLS)

Los permisos se aplican a nivel de base de datos usando RLS de PostgreSQL:

```sql
-- Política para que viewers solo puedan leer
CREATE POLICY "Viewers can only read practices"
ON practices
FOR SELECT
USING (
    EXISTS (
        SELECT 1 FROM users
        WHERE users.id = auth.uid()
        AND users.lab_id = practices.lab_id
    )
);

-- Política para que users puedan crear
CREATE POLICY "Users can create practices"
ON practices
FOR INSERT
WITH CHECK (
    EXISTS (
        SELECT 1 FROM users
        WHERE users.id = auth.uid()
        AND users.lab_id = practices.lab_id
        AND users.role IN ('user', 'admin')
    )
);

-- Política para que solo admins puedan eliminar
CREATE POLICY "Only admins can delete practices"
ON practices
FOR DELETE
USING (
    EXISTS (
        SELECT 1 FROM users
        WHERE users.id = auth.uid()
        AND users.lab_id = practices.lab_id
        AND users.role = 'admin'
    )
);
```

### Middleware de Autorización

En el código de Next.js, se valida el rol antes de ejecutar acciones:

```typescript
// lib/auth.ts
export async function requireRole(
  requiredRole: 'admin' | 'user' | 'viewer'
) {
  const user = await getCurrentUser();

  if (!user) {
    throw new Error('Not authenticated');
  }

  const roleHierarchy = {
    admin: 3,
    user: 2,
    viewer: 1
  };

  if (roleHierarchy[user.role] < roleHierarchy[requiredRole]) {
    throw new Error('Insufficient permissions');
  }

  return user;
}
```

```typescript
// app/api/practices/route.ts
export async function DELETE(request: Request) {
  // Solo admins pueden eliminar
  await requireRole('admin');

  // ... resto del código
}
```

### Componentes del Frontend

Los componentes verifican permisos antes de renderizar:

```tsx
// components/DeleteButton.tsx
import { useUser } from '@/lib/hooks/use-user';

export function DeleteButton({ practiceId }: Props) {
  const { user } = useUser();

  // Solo mostrar el botón si es admin
  if (user?.role !== 'admin') {
    return null;
  }

  return (
    <Button onClick={() => deletePractice(practiceId)}>
      Eliminar
    </Button>
  );
}
```

## Auditoría

Todos los cambios de roles quedan registrados en la tabla `audit_log`:

```sql
CREATE TABLE audit_log (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    lab_id UUID REFERENCES labs(id),
    user_id UUID REFERENCES users(id),
    action TEXT NOT NULL,
    entity_type TEXT NOT NULL,
    entity_id UUID,
    old_values JSONB,
    new_values JSONB,
    timestamp TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

Ejemplo de registro:

```json
{
  "action": "role_changed",
  "entity_type": "user",
  "entity_id": "user_123",
  "old_values": { "role": "viewer" },
  "new_values": { "role": "user" },
  "changed_by": "admin_456"
}
```

## Seguridad

<Warning>
Nunca compartas credenciales de admin. Crea usuarios individuales para cada persona.
</Warning>

### Recomendaciones

- Usa contraseñas fuertes (mínimo 12 caracteres)
- Habilita autenticación de dos factores (próximamente)
- Revoca acceso inmediatamente cuando alguien deja el laboratorio
- Monitorea el audit log regularmente
